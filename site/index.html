What the free check looks at

It reads files in your repo, and with --home your agent configs too. No network, no database, no account.

B1 B2Keys an agent can read

  • service_role and sb_secret_ keys in files, .env and your built frontend
  • Keys in VITE_ or NEXT_PUBLIC_ variables, which ship to every visitor
  • Supabase access tokens and database passwords

B3 B4Supabase MCP server

  • Not read-only, so the agent can change data and drop tables
  • Not limited to one project, so it reaches your whole account

B6Claude Code rules

  • Would it stop supabase db reset --linked, supabase projects delete or drop table?
  • Can it read .env without asking?
  • Is it in bypassPermissions mode?

B7Backups

  • Is there a dump job that stores a copy outside Supabase?

Run it in one minute

Python 3.11 or newer. Nothing else to install. It exits with code 1 on any critical finding, so it can fail a CI job.

On your machine

git clone https://github.com/karthikkushi/karchi-guard
cd karchi-guard
PYTHONPATH=src python3 -m karchi_guard scan /path/to/your/app

In GitHub Actions

- uses: actions/checkout@v4
- uses: karthikkushi/karchi-guard@v0

Honest limits

I never

  • Scan or test an app without the owner's written permission
  • Connect to your live database or copy user data
  • Upload your code or keys anywhere. The free check runs on your machine
  • Call an app "100% secure"

The free check does not cover

  • RLS policies. Run supabase db advisors --type security
  • Whether user A can read user B's rows. The $49 fix tests this
  • Keys in old git commits. Run gitleaks
  • Cursor and Windsurf command allowlists

Questions

Do you need my Supabase keys?

No. The free check reads files on your machine. For the $49 fix I only need the repo, or a schema-only dump with no data. Keys that leaked should be rotated by you, in your own dashboard.

Supabase already has a Security Advisor. Why do I need this?

Use the Advisor; the fix includes it. It checks your database rules. It does not check what your AI agent can reach. In our test app it also missed a policy that let any logged-in user read every order. The user A vs user B test caught it.
